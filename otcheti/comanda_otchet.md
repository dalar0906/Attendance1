# Сводный отчёт команды — Спринт 3

**Участники:** Кудашова Мария, Ларионова Дарья, Брюханов Бронислав

## 1. Цель спринта

Реализовать сценарий создания занятия и отметки статуса посещаемости для каждого студента. Преподаватель должен иметь возможность выбрать группу и дату, открыть список студентов и назначить каждому один из трёх статусов посещаемости.

- **Lead Developer (LD) — Брюханов Бронислав**

- Согласовать статусы «Присутствовал», «Отсутствовал», «Опоздал».
- Определить правило одной итоговой отметки на студента и занятие.
- Сверять реализацию с пользовательской историей US-05.
- Участвовать в приёмочных сценариях и демонстрации.

- Реализовать сохранение выбранных статусов.
- Предусмотреть возможность изменения статуса до окончательного сохранения.
- Согласовать изменения с командой и проверить сборку после интеграции.

### QA / DevOps — Кудашова Мария

## 4. Основной пользовательский сценарий

1. Преподаватель открывает экран посещаемости.
2. Выбирает группу и дату занятия.
3. Открывает список студентов выбранной группы.
4. Для каждого студента выбирает статус: «Присутствовал», «Отсутствовал» или «Опоздал».
5. При необходимости меняет статус до окончательного сохранения.
6. Сохраняет итоговые отметки.

Для одного студента в рамках одного занятия должна определяться одна итоговая отметка. Если список студентов пуст, приложение должно показать понятное сообщение.

## 5. Результат, предусмотренный планом спринта

- Экран занятия.
- Список студентов выбранной группы с возможностью выбора статуса.
- Сохранение отметок в текущем сеансе приложения.
- Тестовые сценарии для проверки посещаемости.

- [ ] Статусы корректно различаются.
- [ ] Изменение статуса до окончательного сохранения работает.
- [ ] Для одного студента и занятия определяется одна итоговая отметка.
- [ ] Пустой список обрабатывается понятным сообщением.
