# User Stories — Система контроля посещаемости студентов

**Проект:** AttendanceControl  
**Документ:** пользовательские истории и критерии приёмки  
**Актуализация:** Спринт 6 (финальная)  
**Статус документа:** утверждён, все истории выполнены

---

## 1. Проблема и цель

Преподаватели ведут учёт посещаемости вручную (журналы, Excel). Из-за этого могут теряться данные, возникать ошибки подсчёта, а подготовка статистики занимает дополнительное время.

**Цель:** создать локальное Android-приложение для списка студентов, отметки посещаемости, истории и статистики. Приложение предназначено для одного устройства и не требует подключения к интернету для основных функций. Для постоянного хранения данных используется Room / SQLite.

## 2. User Stories

### US-01. Главный экран

**Как** преподаватель, **я хочу** видеть меню с понятными кнопками, **чтобы** быстро перейти к нужной функции.

Критерии:
- [x] На экране отображается название приложения.
- [x] Есть кнопки «Студенты», «Отметить посещаемость», «Статистика».
- [x] Кнопки реагируют на нажатие.

**Статус:** ✅ выполнено (Спринт 1).  
**Тест-кейсы:** TC-01, TC-02.

### US-02. Список студентов

**Как** преподаватель, **я хочу** видеть фамилию, имя и группу студента, **чтобы** понимать, кого отмечаю.

Критерии:
- [x] Список отображается на `StudentsActivity`.
- [x] Видны фамилия, имя и группа.
- [x] При пустом списке отображается сообщение: «Список студентов пуст. Нажмите „Добавить“, чтобы создать первого».
- [x] Список обновляется после добавления или удаления.
- [x] Список сортируется по фамилии.

**Статус:** ✅ выполнено (Спринт 2).  
**Тест-кейсы:** TC-03, TC-11, TC-12.

### US-03. Добавление студента

**Как** преподаватель, **я хочу** добавлять студента (фамилия, имя, группа), **чтобы** вести актуальный список.

Критерии:
- [x] Есть форма с тремя полями.
- [x] Все поля обязательны.
- [x] Пустые поля и поля из пробелов отклоняются.
- [x] Слишком короткие и слишком длинные значения отклоняются.
- [x] Дубликат, у которого совпадают все три поля, отклоняется.
- [x] После добавления студент появляется в списке и показывается сообщение «Студент добавлен».

**Статус:** ✅ выполнено (Спринт 2).  
**Тест-кейсы:** TC-05, TC-06, TC-07, TC-08, TC-09.

### US-04. Удаление студента

**Как** преподаватель, **я хочу** удалять студента, **чтобы** убирать ошибочные записи.

Критерии:
- [x] У каждой записи есть действие удаления.
- [x] Перед удалением отображается диалог подтверждения с ФИО.
- [x] После подтверждения список обновляется.
- [x] Показывается сообщение «Студент удалён».
- [x] Удаление не вызывает аварийного завершения приложения.

**Статус:** ✅ выполнено (Спринт 2).  
**Тест-кейсы:** TC-10.

### US-05. Отметка посещаемости

**Как** преподаватель, **я хочу** отмечать статус студента, **чтобы** фиксировать посещаемость на занятии.

Критерии:
- [x] Можно выбрать группу и дату.
- [x] Для каждого студента можно выбрать один из трёх статусов: «Присутствовал», «Отсутствовал», «Опоздал».
- [x] Статус можно изменить до окончательного сохранения.
- [x] При пустом списке отображается понятное сообщение.
- [x] Для одного студента в рамках одного занятия сохраняется одна итоговая отметка.

**Статус:** ✅ выполнено (Спринт 3).  
**Тест-кейсы:** TC-13…TC-23.

### US-06. Статистика и фильтрация

**Как** преподаватель, **я хочу** видеть присутствия, пропуски и опоздания и фильтровать их по студенту, группе и дате, **чтобы** понимать общую картину посещаемости.

Критерии:
- [x] Есть экран статистики.
- [x] Отображаются показатели: занятия, присутствия, пропуски и опоздания.
- [x] Сумма статусов равна количеству занятий.
- [x] Фильтр по студенту работает.
- [x] Фильтр по группе работает.
- [x] Фильтр по дате работает.
- [x] Комбинированный фильтр (группа + дата) корректен.
- [x] Фильтр сбрасывается при выходе с экрана (BUG-02 исправлен).
- [x] При отсутствии данных отображается сообщение «Нет данных» (BUG-01 исправлен).
- [x] Статистика сохраняется между запусками (Room).

**Тест-кейсы:** TC-37, TC-38, TC-40, TC-41, TC-42, TC-43, TC-44, TC-45, TC-47, TC-48, TC-50, TC-51.

**Статус:** ✅ выполнено (Спринт 5, дефекты закрыты в Спринте 6).

### US-07. Сохранение между запусками

**Как** преподаватель, **я хочу**, чтобы список студентов, занятия и отметки посещаемости сохранялись между запусками приложения, **чтобы** не вводить данные повторно.

Критерии:
- [x] Данные студентов сохраняются в локальной базе Room.
- [x] После полного закрытия и повторного запуска приложения ранее добавленные студенты отображаются.
- [x] Занятия и отметки посещаемости сохраняются в Room.
- [x] После повторного запуска ранее сохранённые отметки доступны.
- [x] Добавление, чтение и удаление данных выполняются через DAO.
- [x] Повторное сохранение не создаёт дублирующие записи там, где должна существовать одна итоговая запись.

**Статус:** ✅ выполнено (Спринт 4, Room).  
**Тест-кейсы:** TC-25, TC-26, TC-27, TC-28, TC-30, TC-32, TC-33, TC-34.

### US-08. Валидация ввода

**Как** преподаватель, **я хочу** получать понятные сообщения об ошибках ввода, **чтобы** быстро исправлять данные.

Критерии:
- [x] Ошибки отображаются у соответствующего поля или в Toast.
- [x] Тексты ошибок соответствуют правилам раздела «Валидация и сообщения».
- [x] После исправления ошибки пользователь может сохранить данные.
- [x] Корректный ввод не блокируется.

**Статус:** ✅ выполнено (Спринт 2).  
**Тест-кейсы:** TC-06, TC-07, TC-08.

## 4. Валидация и сообщения

Все поля формы студента обязательны.

- **Фамилия:** 2–40 символов, кириллица и дефис.
- **Имя:** 2–30 символов, кириллица и дефис.
- **Группа:** 2–15 символов, кириллица, цифры и дефис.

Дополнительные правила:

- Перед проверкой значения обрезаются с помощью `trim()`.
- Поле не должно быть пустым или состоять только из пробелов.
- Дубликатом считается запись, у которой совпадают фамилия, имя и группа.
- Список сортируется по фамилии.

Сообщения:

- Успех: «Студент добавлен».
- Пустые поля: «Заполните обязательные поля».
- Только пробелы: «Поле не может состоять только из пробелов».
- Слишком короткое значение: «Слишком короткое значение (мин. 2 символа)».
- Слишком длинное значение: «Слишком длинное значение (макс. 40 символов)».
- Дубликат: «Такой студент уже есть в списке».
- Пустой список: «Список студентов пуст. Нажмите „Добавить“, чтобы создать первого».
- Подтверждение удаления: «Удалить студента <Фамилия Имя>? Действие нельзя отменить».
- Удаление: «Студент удалён».
- Нет данных в статистике: «Нет данных».

## 5. Приёмочные сценарии

- **AC-01. Пустой список:** отображается сообщение о пустом списке студентов.
- **AC-02. Добавление студента:** после добавления тестового студента он отображается в списке и появляется сообщение «Студент добавлен».
- **AC-03. Пустая фамилия:** система просит заполнить обязательные поля.
- **AC-04. Фамилия из пробелов:** система сообщает, что поле не может состоять только из пробелов.
- **AC-05. Дубликат:** повторная запись с теми же фамилией, именем и группой отклоняется.
- **AC-06. Удаление с подтверждением:** студент удаляется из списка, отображается сообщение «Студент удалён».
- **AC-07. Отмена удаления:** после выбора «Отмена» студент остаётся в списке.
- **AC-08. Сохранение:** после полного перезапуска данные остаются доступными (Room).
- **AC-09. Статистика:** показатели совпадают с тестовыми данными; сумма статусов равна количеству занятий.
- **AC-10. Фильтры:** фильтрация по студенту, группе и дате работает; комбинированный фильтр корректен.
- **AC-11. Пустая история:** при отсутствии отметок отображается сообщение «Нет данных».
- **AC-12. Сброс фильтра:** при выходе с экрана статистики фильтр сбрасывается.

## 7. Примечания Product Owner

- Интерфейс и сообщения приложения — на русском языке.
- ФИО вводятся кириллицей с возможностью использования дефиса.
- Группа может содержать кириллицу, цифры и дефис.
- Дубликат определяется совпадением всех трёх полей: фамилии, имени и группы.

- Room / SQLite используется для постоянного хранения данных; временная коллекция `MutableList` не должна оставаться основным хранилищем после завершения Спринта 4.

- На момент сдачи приложения все User Stories (US-01…US-08) выполнены; открытых дефектов нет.
