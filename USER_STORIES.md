# User Stories — Система контроля посещаемости студентов

**Проект:** AttendanceControl  
**Документ:** пользовательские истории и критерии приёмки  
**Актуализация:** Спринт 4

---

## 1. Проблема и цель

Преподаватели ведут учёт посещаемости вручную (журналы, Excel). Из-за этого могут теряться данные, возникать ошибки подсчёта, а подготовка статистики занимает дополнительное время.

**Цель:** создать локальное Android-приложение для списка студентов, отметки посещаемости, истории и статистики. Приложение предназначено для одного устройства и не требует подключения к интернету для основных функций. Для постоянного хранения данных используется Room / SQLite.

## 2. User Stories

### US-01. Главный экран

**Как** преподаватель, **я хочу** видеть меню с понятными кнопками, **чтобы** быстро перейти к нужной функции.

Критерии:
- [x] На экране отображается название приложения.
- [x] Есть кнопки «Студенты», «Отметить посещаемость», «Статистика».
- [x] Кнопки реагируют на нажатие.

**Статус:** выполнено (Спринт 1).

### US-02. Список студентов

**Как** преподаватель, **я хочу** видеть фамилию, имя и группу студента, **чтобы** понимать, кого отмечаю.

Критерии:
- [ ] Список отображается на `StudentsActivity`.
- [ ] Видны фамилия, имя и группа.
- [ ] При пустом списке отображается сообщение: «Список студентов пуст. Нажмите „Добавить“, чтобы создать первого».
- [ ] Список обновляется после добавления или удаления.
- [ ] Список сортируется по фамилии.

**Статус:** Спринт 2.

### US-03. Добавление студента

**Как** преподаватель, **я хочу** добавлять студента (фамилия, имя, группа), **чтобы** вести актуальный список.

Критерии:
- [ ] Есть форма с тремя полями.
- [ ] Все поля обязательны.
- [ ] Пустые поля и поля из пробелов отклоняются.
- [ ] Слишком короткие и слишком длинные значения отклоняются.
- [ ] Дубликат, у которого совпадают все три поля, отклоняется.
- [ ] После добавления студент появляется в списке и показывается сообщение «Студент добавлен».

**Статус:** Спринт 2.

### US-04. Удаление студента

**Как** преподаватель, **я хочу** удалять студента, **чтобы** убирать ошибочные записи.

Критерии:
- [ ] У каждой записи есть действие удаления.
- [ ] Перед удалением отображается диалог подтверждения с ФИО.
- [ ] После подтверждения список обновляется.
- [ ] Показывается сообщение «Студент удалён».
- [ ] Удаление не вызывает аварийного завершения приложения.

**Статус:** Спринт 2.

### US-05. Отметка посещаемости

**Как** преподаватель, **я хочу** отмечать статус студента, **чтобы** фиксировать посещаемость на занятии.

Критерии:
- [ ] Можно выбрать группу и дату.
- [ ] Для каждого студента можно выбрать один из трёх статусов: «Присутствовал», «Отсутствовал», «Опоздал».
- [ ] Статус можно изменить до окончательного сохранения.
- [ ] При пустом списке отображается понятное сообщение.
- [ ] Для одного студента в рамках одного занятия сохраняется одна итоговая отметка.

**Статус:** Спринт 3.

### US-06. Статистика

**Как** преподаватель, **я хочу** видеть присутствия, пропуски и опоздания, **чтобы** понимать общую картину посещаемости.

Критерии:
- [ ] Есть экран статистики.
- [ ] Отображаются показатели: занятия, присутствия, пропуски и опоздания.
- [ ] При отсутствии данных отображается понятное сообщение.

**Статус:** Спринт 5.

### US-07. Сохранение между запусками

**Как** преподаватель, **я хочу**, чтобы список студентов, занятия и отметки посещаемости сохранялись между запусками приложения, **чтобы** не вводить данные повторно.

Критерии:
- [ ] Данные студентов сохраняются в локальной базе Room.
- [ ] После полного закрытия и повторного запуска приложения ранее добавленные студенты отображаются.
- [ ] Занятия и отметки посещаемости сохраняются в Room.
- [ ] После повторного запуска ранее сохранённые отметки доступны.
- [ ] Добавление, чтение и удаление данных выполняются через DAO.
- [ ] Повторное сохранение не создаёт дублирующие записи там, где должна существовать одна итоговая запись.

**Статус:** Спринт 4 (Room).

### US-08. Валидация ввода

**Как** преподаватель, **я хочу** получать понятные сообщения об ошибках ввода, **чтобы** быстро исправлять данные.

Критерии:
- [ ] Ошибки отображаются у соответствующего поля или в Toast.
- [ ] Тексты ошибок соответствуют правилам раздела «Валидация и сообщения».
- [ ] После исправления ошибки пользователь может сохранить данные.
- [ ] Корректный ввод не блокируется.

**Статус:** Спринт 2.

## 3. Экраны

### Главное меню — `MainActivity`

- Название приложения.
- Кнопка «Студенты».
- Кнопка «Отметить посещаемость».
- Кнопка «Статистика».

### Студенты — `StudentsActivity`

- Список студентов.
- Отображение фамилии, имени и группы.
- Добавление и удаление студентов.

### Посещаемость — `AttendanceActivity`

- Выбор группы.
- Выбор даты занятия.
- Список студентов выбранной группы.
- Выбор статуса посещаемости для каждого студента.

### Статистика — `StatisticsActivity`

- Количество занятий.
- Количество присутствий.
- Количество пропусков.
- Количество опозданий.

## 4. Валидация и сообщения

Все поля формы студента обязательны.

- **Фамилия:** 2–40 символов, кириллица и дефис.
- **Имя:** 2–30 символов, кириллица и дефис.
- **Группа:** 2–15 символов, кириллица, цифры и дефис.

Дополнительные правила:

- Перед проверкой значения обрезаются с помощью `trim()`.
- Поле не должно быть пустым или состоять только из пробелов.
- Дубликатом считается запись, у которой совпадают фамилия, имя и группа.
- Список сортируется по фамилии.

Сообщения:

- Успех: «Студент добавлен».
- Пустые поля: «Заполните обязательные поля».
- Только пробелы: «Поле не может состоять только из пробелов».
- Слишком короткое значение: «Слишком короткое значение (мин. 2 символа)».
- Слишком длинное значение: «Слишком длинное значение (макс. 40 символов)».
- Дубликат: «Такой студент уже есть в списке».
- Пустой список: «Список студентов пуст. Нажмите „Добавить“, чтобы создать первого».
- Подтверждение удаления: «Удалить студента <Фамилия Имя>? Действие нельзя отменить».
- Удаление: «Студент удалён».

## 5. Приёмочные сценарии

- **AC-01. Пустой список:** отображается сообщение о пустом списке студентов.
- **AC-02. Добавление студента:** после добавления тестового студента он отображается в списке и появляется сообщение «Студент добавлен».
- **AC-03. Пустая фамилия:** система просит заполнить обязательные поля.
- **AC-04. Фамилия из пробелов:** система сообщает, что поле не может состоять только из пробелов.
- **AC-05. Дубликат:** повторная запись с теми же фамилией, именем и группой отклоняется.
- **AC-06. Удаление с подтверждением:** студент удаляется из списка, отображается сообщение «Студент удалён».
- **AC-07. Отмена удаления:** после выбора «Отмена» студент остаётся в списке.
- **AC-08. Сохранение:** после полного перезапуска данные должны оставаться доступными при использовании Room.

- **Спринт 1:** US-01 — главный экран.

- **Спринт 3:** US-05 — создание занятия и отметка посещаемости.

## 7. Примечания Product Owner

- Интерфейс и сообщения приложения — на русском языке.
- ФИО вводятся кириллицей с возможностью использования дефиса.
- Группа может содержать кириллицу, цифры и дефис.
- Дубликат определяется совпадением всех трёх полей: фамилии, имени и группы.
- Для демонстрации используются только вымышленные данные.
- Приложение рассчитано на локальную работу на одном Android-устройстве.
- Room / SQLite используется для постоянного хранения данных; временная коллекция `MutableList` не должна оставаться основным хранилищем после завершения Спринта 4.
- Отдельная сущность `Lesson` не считается утверждённой до согласования с Lead Developer.
